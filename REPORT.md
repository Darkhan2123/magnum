# Отчёт: распознавание овощей по фото (трек A)

## 1. Что я нашёл в данных

Подробно с кодом и картинками: `notebooks/01_data_analysis.ipynb`.

* **Реальных картинок 3879, а не 9300.** `final_dataset` не содержит ни одной новой картинки, все файлы скопированы из `Dataset/` (проверил по md5).
* **Как получены.** Имена файлов это время съёмки на телефоне, `_frame_N` это кадр из видео. По факту это **19 видео** (3694 кадра 200x200, 95% данных) и **185 фото** (полноразмерные, одна камера Samsung A53), снятые **за 4 дня**. В одном видео от 24 до 607 кадров, на класс 2-6 видео, у Raddish один день съёмки.
* Всё снято **на одной тёмной столешнице дома**, часто в руке. Raddish это белый дайкон, Squash это чайот, Capsicum только зелёный. У фото в EXIF поворот, без `exif_transpose` они лежат боком. Дисбаланс 4.7 раза (Squash 1343, Raddish 286).
* **Дубликаты.** Точных внутри `Dataset/` нет. Почти-дубликаты искал через phash (Хэмминг ≤ 10) и косинусную близость эмбеддингов ResNet18: у 3161 из 3879 картинок есть почти-копия, 12155 из 12161 пар это кадры одного видео. phash даёт и ложные пары между классами (один овощ на тёмном фоне), поэтому группы строил по видео и дню из имени файла.
* **Готовому разбиению доверять нельзя.** 717 из 799 картинок test (90%) это побайтные копии train, ещё 75 это соседние кадры тех же видео. С val то же самое.

## 2. Моё разбиение (`make_split.py`)

* **test** = целый день съёмки для каждого класса (модель не видит ни этот день, ни его видео), примерно 20-40% класса. У Raddish день один, поэтому для него test это второе видео и фото после него (проверка слабее).
* **val** = куски видео по 50 кадров и серии фото из остальных дней. Он оптимистичный и нужен только для выбора эпохи.
* train 2252 / val 567 / test 1060 (в test 17 групп). У моего test нет картинок с близостью > 0.95 к train (медиана 0.84), у test автора таких 98.6%.

## 3. Модель

ResNet18 (ImageNet), новый слой на 6 классов, дообучаю всю сеть: Adam 1e-4, cosine, 10 эпох, batch 32, 224 px, CrossEntropy с весами классов. Лучшая эпоха по val macro-F1 (при равенстве по val loss).
Аугментации: `RandomResizedCrop(0.6-1)`, потому что в магазине овощ не всегда крупно по центру; отражение и поворот до 15°; `ColorJitter` яркости/контраста/насыщенности под другой свет. Оттенок почти не трогаю, цвет тут главный признак.
На test и в predict меньшая сторона -> 224 + центральный квадрат (фото 2084x4624 не сплющиваю).

## 4. Результаты

| проверка | accuracy | macro-F1 |
|---|---|---|
| test автора (модель на train автора) | 1.000 | 1.000 |
| мой val | 1.000 | 1.000 |
| **мой test** | **0.854** | **0.841** |
| мой test, только фото (43 шт) | 0.953 | 0.933 |

По классам (precision / recall / F1): Capsicum 0.88/0.63/0.73, Carrot 0.98/0.91/0.95, Cucumber 0.48/0.90/0.63, Potato 1.00/0.74/0.85, Raddish 0.90/0.98/0.94, Squash 1.00/0.91/0.95.

* Главная ошибка: в Cucumber уходят зелёный Capsicum (63 из 171), часть Potato (25) и Squash (25). Ошибки сидят в нескольких видео теста, одно видео Capsicum даёт 64 из 155. Думал, что виноват вес класса Cucumber (2.9), но без весов accuracy та же, а путаница разворачивается (Cucumber уходит в Capsicum, 75 кадров). Кроме похожего цвета, модель, похоже, частично запомнила условия съёмки: из 76 ошибок на видео 13 ноября 60 ушли в Cucumber, а это единственный класс с видео этого дня в train (Grad-CAM на таких ошибках смотрит на фон). Модель с весами оставил, она была выбрана до просмотра test.
* **Grad-CAM** (`reports/figures/gradcam.png`): на правильных примерах модель смотрит на овощ. На ошибках смотрит на фон между овощами, рядом с рукой или на кусок овоща у края. Carrot -> Raddish на пересвеченном кадре, где морковь почти белая.
* **Искажения test** (accuracy): без изменений 0.854, темнее 0.892, тёплый свет 0.800, размытие 0.813, JPEG q15 0.812, овощ в 2 раза меньше на светлом фоне 0.808. Средняя уверенность почти не падает (0.77-0.88), то есть модель ошибается уверенно.
* **CPU** (i5-12500H, batch 1): сеть около 21 мс; от файла до ответа 23 мс для кадра 200x200 и 153 мс для фото 9.6 Мп (почти всё это чтение JPEG). От запуска к запуску время плавает примерно на 10%. Загрузка модели 0.13 с.

## 5. Чего ожидаю на ваших фото из магазина

Заметно ниже 85%, я бы ожидал примерно 50-70%. Причины: (1) новый день съёмки дома уже дал минус 15% к val, а магазин отличается сильнее: фон, ценники, пакеты, свет, камера; (2) в данных овощ крупно и 1-10 штук, на полке их много и они мелкие, а модель классифицирует всю картинку; (3) если в магазине красный редис, кабачок и цветной перец, модель таких не видела (кабачок, скорее всего, уйдёт в Cucumber); (4) нет класса "нет овоща", пустая полка всё равно получит один из 6 классов.

## 6. Что не получилось

* Val показывает 1.0 с первой эпохи и для выбора эпохи бесполезен. Нужна кросс-валидация по дням (leave-one-day-out), не успел.
* В test 17 независимых групп, поэтому 0.854 шумная оценка. Несколько сидов и доверительные интервалы не считал.
* Test для Raddish из того же дня, что и train, его 0.94 скорее завышено.
* Бонусы (unknown, ONNX) не делал. Проверить на настоящих фото из магазина не мог.

## 7. Что бы сделал дальше

1. Собрать 50-100 фото на класс в разных магазинах и валидироваться на них, добавить нужные сорта.
2. Leave-one-day-out кросс-валидация и несколько сидов.
3. Класс unknown (порог уверенности на фото без этих овощей).
4. Для полок детекция (YOLO) или классификация кропов вместо всей картинки.
5. Аугментации фона (вставка овощей на фоны магазинов), random erasing против опоры на руки.
6. Ускорить чтение больших JPEG (`Image.draft`), ONNX.
